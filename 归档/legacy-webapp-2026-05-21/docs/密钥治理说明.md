# 密钥治理说明

## 目标

这个项目的密钥治理遵循四条原则：

1. **代码中不硬编码真实密钥**
2. **仓库不追踪本地 `.env` / Cookie / 私钥文件**
3. **文档、日志、截图、报错中只出现脱敏值**
4. **历史一旦发现泄漏，优先换 Key，再清历史**

---

## 当前规范变量

### Google GenAI / Gemini

主变量：

- `GOOGLE_GENAI_API_KEY`
- `GOOGLE_GENAI_MODEL`

兼容旧变量（保留读取，但不建议继续新增使用）：

- `GOOGLE_AI_KEY`
- `GEMINI_API_KEY`
- `GEMINI_MODEL`

### 其他模型

- `OPENAI_API_KEY`
- `OPENROUTER_API_KEY`
- `DEEPSEEK_API_KEY`
- `CODEX_PATH`
- `CODEX_MODEL`

---

## 文件约定

### 可提交

- `config/.env.example`
- 不包含真实凭证的说明文档
- 脱敏后的日志/审计报告

### 禁止提交

- `config/.env`
- `webapp/.env`
- `config/xhs_cookies.json`
- 任意 `*.pem` / `*.key` / `*.p12` / `*.pfx`
- 任意本地 secrets 文件夹

---

## 脱敏规则

展示密钥时，只允许以下形式：

- Google: `AIza***MASKED***`
- OpenRouter: `sk-or-v1-***MASKED***`
- 其他 `sk-`：`sk-***MASKED***`
- 通用变量赋值：`XXX_API_KEY=***MASKED***`

禁止在以下位置输出完整密钥：

- 文档
- Commit message
- Issue / PR
- 日志
- 截图
- 调试回显

---

## 本地自检

### 扫描当前工作区

```bash
python tools/compliance/secret_scan.py
```

### 扫描 git 历史

```bash
python tools/compliance/secret_scan.py --git
```

如果扫描命中：

1. **先失效 / 轮换对应 Key**
2. 修正工作区文件
3. 再处理 git 历史

---

## 历史清理原则

- 优先使用专门工具（`git-filter-repo` / BFG）
- 如果当前工作树很脏，不直接在主工作目录硬改历史
- 先在镜像/临时克隆中完成历史改写，再决定是否替换主仓库引用

建议顺序：

1. 创建临时镜像仓库
2. 改写历史中的敏感值/敏感文件
3. 运行 `git fsck` / secret scan 复检
4. 确认后再 force push / 替换主分支

---

## 轮换建议

发现泄漏时，不要只做“删文件”。正确顺序是：

1. **立即废弃旧 Key**
2. 生成新 Key
3. 更新本地 `config/.env`
4. 验证功能恢复
5. 清理历史与文档残留

---

## 备注

这个文档是项目级安全约束，不是一次性说明。后续新增模型接入时，先补变量规范，再接代码。
