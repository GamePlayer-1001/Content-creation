# 内容生成输出项目 - 项目主线方案

更新时间：2026-03-24
状态：主线定版（合并稿）

---

## 一、项目定位

项目目标是建设一个可持续的内容生产系统，而非零散脚本集合。系统形态为：

- WebApp 作为主操作面（人工主导）
- CLI 作为并行通道（批处理与自动化友好）
- Shared Service / Pipeline 作为唯一执行核心
- Google Sheets 作为热点输入池（优先方案）
- 内容生产采用串行流程并保留人工确认

当前阶段结论：暂不接入 cron。

---

## 二、统一原则（合并去重后）

1. 双通道，不双实现
WebApp 与 CLI 都是完整入口，但必须共用底层逻辑，避免两套实现。

2. 差异只在交互形态
WebApp 侧重可视化编辑与预览；CLI 侧重命令式推进、批处理和日志化。

3. 主流程保留人工控制权
系统是 Human-in-the-loop，关键节点允许人工删改、确认、回退和局部重跑。

4. 热点采集与内容生产解耦
热点由外部能力沉淀到 Google Sheets，项目侧负责读取、筛选、导入与创作。

5. 先收口后扩展
先统一流程、状态、配置、目录与入口，再考虑接入调度体系。

---

## 三、统一主流程（9阶段）

1. 读取热点池（Google Sheets）
2. 选择热点
3. 补录热点详细信息
4. 生成母稿
5. 多平台改写
6. 审核优化 / 去 AI 味
7. 生成视觉素材
8. 排版组装
9. 导出输出并可追溯打开

流程规则：
- 上一步自动承接到下一步
- 每一步允许人工修订后再继续
- 支持阶段回退、单步重跑、区间重跑

---

## 四、目标架构（5层）

### L1 输入源层
Google Sheets 热点池、手动输入、模板与规则资产。

### L2 应用层
- WebApp：图形化完整操作面
- CLI：命令化完整操作面

### L3 编排层
统一阶段定义、任务状态、续跑/重试策略、检查点与产物索引。

### L4 共享服务层
建议长期收口为以下能力：
- Hotspot Service
- Draft Service
- Rewrite Service
- Review Service
- Visual Service
- Layout Service
- Export Service
- Config Service
- Storage / Asset Registry

### L5 资产与输出层
模板、规则、视觉资产、输出结果、日志和复盘沉淀。

---

## 五、目录收口目标（规划口径）

推荐未来顶层语义：

- `app/`：WebApp + CLI 入口
- `core/`：共享 services / pipeline / adapters
- `config/`：配置中心
- `assets/`：静态素材
- `knowledge/`：文档知识层
- `output/`：产物与日志
- `scripts/`：辅助脚本
- `archive/`：历史遗留

当前映射方向（简化版）：
- `webapp/` -> `app/webapp`
- `tools/` -> `core + scripts + archive`（按能力拆分）
- `.md/ + docs/` -> `knowledge`
- `web hot/` -> `output/hotspots`（或同语义目录）
- `排除/` -> `archive`

## 六、当前阶段实施边界

当前应优先完成：

1. 统一任务状态模型与阶段定义
2. WebApp / CLI 双通道能力对齐
3. 抽离共享 service / pipeline
4. 统一配置口径与环境变量
5. 清理重复脚本与历史入口

当前不做：
- 直接大规模物理搬迁目录
- 将系统强行并入 cron 全自动链路

---

## 七、当前实现快照（2026-03-24）

已落地：

1. 统一阶段定义与任务状态
- WebApp / CLI 共享 `core/pipeline/stages` 与任务状态文件。

2. 人工确认机制恢复生效
- 需要确认的阶段会进入 `awaiting_confirmation`，不会再被默认自动放行。

3. 已支持显式回退与局部重跑
- 任务可回退到指定阶段，并重新执行该阶段或继续区间执行。

4. 续跑信息可追溯
- Web / CLI 的 `run-range` 结果都会写回任务元数据，供摘要卡、续跑与诊断使用。

仍未完成：

1. Web 流水线仍是 5 组分组视图
- 当前只是承载 9 阶段，不是 9 阶段逐步 UI。

2. 共享执行链尚未完全收口
- 热点三阶段已共用 step executor，但 draft / platform / review / compose / export 仍存在 Web 路由遗留实现。

3. 自动化测试体系尚未重建
- 历史 Python 测试多数已脱轨，需要用新的 shared pipeline smoke tests 接管。

---

## 八、验收标准（主线）

- 新人可在 3 分钟内理解主流程
- WebApp 与 CLI 可对同一任务跨通道续接
- 核心逻辑单处维护，不再双份复制
- 任一成品可追溯到完整生产链路
