## 二、统一标签体系（历史口径）

- 标签 A：主应用主干（Primary App）
- 标签 B：共享核心候选（Core Candidate）
- 标签 C：配置/资产层（Config/Asset）
- 标签 D：知识文档层（Knowledge）
- 标签 E：输出结果层（Output）
- 标签 F：辅助脚本/历史遗留/待判定（Script/Legacy/Review）

## 三、历史结论（收口版）

1. 项目后续应按语义层收口，而不是按历史来源堆叠。
2. `tools/` 不适合继续作为单一总目录长期承载所有能力。
3. `.md/` 与 `docs/` 应统一升级为知识层（knowledge）。
4. `output/` 与热点结果应统一纳入结果层并建立可追溯结构。
5. 历史材料与临时目录应显式归档，不再混入主干叙事。

---

## 四、`tools/` 历史标签结论（摘要）

高优先梳理对象：
- `tools/generator/`
- `tools/scraper/`
- `tools/compliance/`
- `tools/publish/`
- `tools/scheduler/`

中优先梳理对象：
- `tools/card/`
- `tools/cover/`
- `tools/screenshot/`
- `tools/video/`
- `tools/jianying/`

偏辅助或历史对象：
- `tools/tests/`
- `tools/utils/`
- `tools/hooks/`
- 单文件工具（如 `manage.py` 等）

建议方向：
- 核心能力进入 `core/`
- 辅助脚本进入 `scripts/`
- 历史实现进入 `archive/`

---

## 五、历史映射结论（摘要）

建议映射：

- `webapp/` -> `app/webapp/`
- `tools/` -> `core/ + scripts/ + archive/`
- `docs/ + .md/` -> `knowledge/`
- `templates/` -> `assets/ + config/rules + knowledge/examples`
- `web hot/` -> `output/hotspots/`
- `排除/` -> `archive/excluded-materials/`

---

## 六、历史迁移优先级（摘要）

Phase 1：先做身份标注与映射表（不搬迁）
Phase 2：先拆语义最乱目录（`tools`、`templates`、`docs/.md`）
Phase 3：再推进主干结构升级（`app/core/knowledge`）
Phase 4：最后修正文档和路径引用
