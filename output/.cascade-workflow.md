# Cascade 方案 A 直生流程自检清单

当用户选择"由我（Cascade）在对话里直接生成文章"时，必须按下列顺序执行，禁止偷工减料：

## 一、强制前置（等价于 style-analyzer.sampleTemplates）

1. 根据目标平台定位范文目录：
   - 公众号 → `content-forge/templates/中文/公众号/`
   - 头条 → `content-forge/templates/中文/头条/`
   - 小红书 → `content-forge/templates/中文/小红书/`
   - Medium/X/Quora/Reddit → `content-forge/templates/英文/`
   - 学术口吻混入 → `content-forge/templates/中文/学术论文/` 或 `英文/academic/`

2. 用 `list_dir` 列目录，随机或按主题相关性挑 **至少 2 篇**，`read_file` 读完整篇。
   - 不能只读 draft-engine.js 里的 PERSONA 常量代替范文。
   - 不能凭印象写。

3. 分析这 2 篇真人稿的：
   - 段落长度分布（不要让一句话段堆叠）
   - 是否大量使用具体数字、专有名词、可核实细节
   - 第二人称频率
   - 金句密度（真人稿通常 1 篇 1–2 个，不是 4–5 个）
   - 小标题风格（陈述句 vs 编号）
   - 结尾收束方式

## 二、写作时禁令

- 禁止"短段堆叠"伪去 AI 味：连续 3 个以上一句话段必须打散。
- 禁止"对仗式金句轰炸"：全文 punchline ≤ 2 处。
- 禁止"某个朋友/有一次"这种零具体物的虚构案例：要么写真实细节，要么不写。
- 禁止"你有没有想过/你知道吗/你猜怎么着"三连反问。
- 数字、工具名、版本号要敢于具体（Coze/Dify/n8n/GPT-4o/Claude 3.5 等）。

## 三、交付前自检

落盘前回读一遍，确认：
- [ ] 段落长度方差合理（混合短/中/长）
- [ ] 至少 5 处可核实的具体物（数字/产品名/事件）
- [ ] 金句数 ≤ 2
- [ ] 小标题是陈述句
- [ ] 结尾不是三连排比

## 四、若用户提供 AI 检测分数

- 不重写整篇，只动检测器最可能打分的句子。
- 给出"动了哪几句、为什么动"的对照表。
