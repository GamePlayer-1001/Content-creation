## 结构体检

### 1. 主入口明确

- 启动器：`start.bat`
- 服务入口：`webapp/server.js`
- 配置主目录：`config/`
- 输出目录：`output/`

优点：入口清晰。
问题：文档里“历史遗留口径”和“当前真实行为”有少量漂移。

### 2. Web 控制台是现在最稳定的主操作面

当前看，`webapp/` 已经形成一个比较完整的本地控制台：

- dashboard
- pipeline
- content
- config
- compliance
- rewrite
- review

这里是后续最值得继续完善的主战场。

### 3. 文档量很大，但存在年代混合

`docs/auto-redbook/` 与历史存档内容很多，适合参考，不适合作为当前真实运行口径。

建议：

- **当前口径**：`CLAUDE.md` + `config/` + `webapp/` 源码
- **历史资料**：`docs/auto-redbook/`

## 模块成熟度判断

### A. 可继续用的核心模块

#### Web 控制台
成熟度：**高**

理由：
- 有明确入口
- 路由和服务层分离
- 已能加载配置、输出、AI 适配、图片生成

#### AIAdapter
成熟度：**中高**

支持：
- Claude CLI
- Codex CLI
- OpenAI
- OpenRouter
- DeepSeek
- Gemini

问题：
- 能力很多，但配置治理此前偏松
- 多引擎并存后，文档和 UI 提示容易漂移

#### 图片生成链路
成熟度：**中**

当前是可用的，但对 Key、模型、提示词模板有较强依赖。
之前最大问题不是功能，而是**安全和配置一致性**。

### B. 可用但需要后续审计的模块

#### tools/publish/
成熟度：**中**

有较多历史脚本，发布逻辑可能存在“版本并存”问题。
后续要重点检查：
- 哪个是当前主脚本
- 哪些是历史备份
- 是否有重复实现

#### tools/scheduler/
成熟度：**中**

有调度器，但需要核对：
- 与当前 `web hot` / cron / OpenClaw 调度之间是否边界清晰
- 是否存在两套调度并行导致重复执行

#### tools/scraper/
成熟度：**中**

更像专项工具集，后续要检查：
- 是否仍符合当前平台抓取路径
- 是否已有脚本过时

### C. 当前明显未完全收口的模块

#### `search` 页面
成熟度：**低**

前端已存在，但从代码注释与现状看，仍偏占位/过渡态，不像最终收口版本。

#### docs 与真实实现对齐度
成熟度：**中低**

文档很多，但部分仍保留旧口径，容易误导后续维护。

## 当前主要风险

### P1 风险：仓库很脏

当前存在大量未提交改动。说明项目正在演进期，不适合直接做“大扫除式重构”。

建议：
- 先分层整理
- 再逐步收敛
- 不要一次性全仓大改

### P1 风险：历史脚本并存

项目融合过多个子项目，目录里明显有“旧模块保留 + 新模块接管”的痕迹。
这会带来两个问题：

1. 同类功能多实现并存
2. 新人难判断哪个是当前主路径

### P1 风险：安全口径此前不统一

本轮已开始修，但后续还要继续：

- 密钥变量统一
- 历史污染点清理
- 文档脱敏
- 防止再次提交本地凭证

## 结论

这个项目不是废墟，反而已经很接近一个可持续运营的本地内容工厂。
真正的问题不在“有没有功能”，而在：

- 变量命名不统一
- 历史包袱较多
- 文档口径漂移
- 安全治理还没完全制度化

也就是说，它现在最需要的不是重新做一个，而是**继续做收口工程**。
